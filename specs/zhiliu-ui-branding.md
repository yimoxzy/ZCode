# 织流桌面 UI 品牌

## 产品规则

织流发行版的应用身份统一使用织流现有品牌，不重新设计图形。唯一视觉来源为织流 SaaS 仓库 `desktop/assets/icon.svg`（白色圆角底、`#24839b` 折线标），复制到 UI 资源目录。启动、标题栏、侧栏、欢迎/更新与应用标识使用这一资源。中文应用名为「织流」，英文为「Zhiliu」。

仅在 `ZHILIU_DESKTOP_ENABLED` 生效；原上游构建的应用标识不变。组件通过 UI 集中的品牌模块读取图形、名称，不改变进程、协议、存储 key 或模型授权。

## 文案边界

国际化仅覆盖明列的应用自述文案，且在变量插值之前转换，不能替换用户姓名、项目文件名、模型名或用户输入中的 ZCode。上游 CDN、ZCode server/CLI、第三方插件、供应商、协议、文件路径与许可证中的真实引用保留。被关闭的上游套餐、奖励、模型供应商服务不冒充织流自营服务。

## 验收

- Windows 标题角标与收起侧栏显示织流折线图标；正常/悬停操作保持原行为。
- React 启动占位与 HTML 启动壳使用同源图形；深浅主题不出现上游 Z 字标。
- 欢迎、更新标识、应用窗口标题与未登录身份使用织流。
- 本地项目的新会话空态在浅色、深色主题均显示织流同源图形，不能因 composer 尚未开放而遗漏 SessionPane 独立渲染的背景标志。
- 中英文启动、欢迎、资源与反馈中的应用名称一致；替换参数中的 `ZCode` 保持原样。
- 关闭织流编译标记时返回上游名称、图标与文案。
- 供应商/文件类型图标、许可证与真实上游技术引用保留。
- 匿名分享时间线的跨版本提示显示织流/ Zhiliu，品牌判断只读取编译标记，不依赖 Desktop 宿主或平台 hook。
- Windows 标题栏菜单与工作区帮助菜单遵循相同服务边界：织流构建隐藏上游问题反馈、需求、社区、文档和更新入口，不查询这些隐藏入口的上游配置；保留资源管理器、日志导出及关于。
- 织流自己的反馈与检查更新入口分别遵循 `zhiliu-feedback-entry.md` 和 `zhiliu-auto-updates.md`；品牌隔离规则不禁止自有服务入口。

本次仅调整展示，不开放本地推理、个人 Key 配置或尚未实现的授权网关。
