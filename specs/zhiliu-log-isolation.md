# 织流桌面诊断数据隔离

## 规则与所有者

- services 路径模块是品牌数据根的唯一所有者；织流诊断导出和模型轨迹读取均通过该根定位文件。
- `ZHILIU_DESKTOP_ENABLED` 开启时，日志导出只读取当前织流数据根内的 CLI 日志、rollout 与 Computer Use 退出日志，不回退、扫描或导入原 `~/.zcode` 数据。
- 织流技术版的日志导出与反馈诊断不收集 CLI `config.json`。该文件可能包含任意供应商、MCP 和自定义凭据，不能依赖键名脱敏保证其安全。
- 已有日志内容脱敏仍生效；原 ZCode 构建保留既有目录与配置诊断行为。
- 模型轨迹读取在织流模式仅查当前数据根；未开启织流模式时保留原 HOME 与自定义根的查找顺序。
- 本变更不创建第二套配置、任务或日志状态，不改变诊断请求与归档的现有接口。

## 验收

1. 在原 ZCode 与织流根放置不同日志、配置和轨迹哨兵；织流 ZIP 仅含织流日志/rollout，两个根的 CLI 配置都不入包。
2. 织流反馈归档的来源不包含原 ZCode 根，也不包含 CLI 配置来源。
3. 相同 session ID 的原 ZCode 轨迹不能覆盖织流轨迹；只有原目录有轨迹时返回无记录。
4. 显式自定义织流数据根继续有效；未开启品牌开关时原目录/自定义根行为与配置诊断均保留。
5. 既有日志脱敏、ZIP/目录回退和轨迹解析回归通过。
