# 真实电脑连接 smoke

本脚本验收已部署服务的设备授权与文件工具 API，使用桌面实际源码中的
`beginZhiliuHostAuthorization` 和 `ZhiliuToolConnection`。它不调用聊天或模型，
不替代 Electron 原生目录选择、审批弹窗及网页交互验收。

## 运行规则

- 服务只能是本机安全隧道 `http://127.0.0.1:18780`；不接受任意远程地址。
- 每次创建随机独立账号，密码、账号令牌、设备私钥和 Host grant 只存在内存。
- 只操作本脚本在系统临时目录创建的专用子目录。自动审批只接受本次创建的请求 ID、
  精确路径和固定测试内容；任何其他请求均拒绝。
- 实际 Host 会生成加密 journal，测试结束删除整个临时目录；不保存凭据文件。
- `finally` 尝试撤销测试设备、注销测试登录并删除临时文件。服务端没有账号删除接口，
  因此保留随机测试账号及设备/授权审计记录。脚本不充值，不发付费请求；注册余额由
  服务端 `initial_credits` 决定，零余额环境应设为 0；验收确认前后余额一致。
- 控制台只输出固定检查说明和计数，不输出账号、设备 ID、连接码、原始响应或异常。

## 命令

从仓库根目录，用 Node 24 及已安装的项目依赖运行：

```powershell
node packages/desktop/scripts/zhiliu-live-computer-smoke.mjs --build-only
node packages/desktop/scripts/zhiliu-live-computer-smoke.mjs
```

`--build-only` 只用 esbuild 打包 fixture 与真实桌面模块，不访问服务，不注册账号。
正式运行前需先部署对应的 desktop-host API 与迁移，并启动本机安全隧道。

## 验收顺序

1. 服务 ready；创建普通独立账号并记录初始余额。
2. 真实 Ed25519/PKCE 授权：确认前 exchange 返回 pending，普通账号核对连接码批准，
   exchange 获得绑定正确用户/空间/设备的窄 grant，重复 exchange 被拒绝。
3. 启动真实 `ZhiliuToolConnection`，由网页 REST 设备列表确认在线且目录已就绪。
4. REST 创建写/读请求，严格核对本机 operation/result review，确认磁盘文件和签名回传结果。
5. 重复轮询不重新审批或执行。第三个已入队写请求停在审批时撤销设备，再放行旧审批，
   确认失效授权阻止落盘；新请求也被拒绝，设备列表显示撤销/离线。
6. 余额不变；撤销设备、注销账号、清理临时目录。

尚未运行的脚本不能作为真实链路已通过的证据。服务部署完成后再运行，原生 UI 验收另记。
