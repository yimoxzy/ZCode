## 可重复同步

```powershell
pnpm sync:zhiliu-upstream
# 已有固定对象时可离线准备：
pnpm sync:zhiliu-upstream -- --ref origin/main --no-fetch
```

命令拒绝脏工作树、错误官方 remote 及已存在分支/目录。没有冲突时留下待验收合并，有冲突时返回非零并列出文件；源工作树不动。后续在输出目录解决兼容问题、安装固定依赖并验收，通过后再提交、推送到 fork 和发布。不能将该命令理解为上游新功能未经校验就自动上线。

首次推送集成分支时，开源 origin 没有官方检查脚本默认使用的 `origin/staging`；使用脚本已支持的 `ZCODE_AFFECTED_TEST_BASE` 显式指定合并前产品提交。本轮使用 `975db9e3aad0d558c95a1e91654dd03b06008e0c`，让架构与受影响测试覆盖本次完整集成范围，保留 pre-push 门禁。后续同步应记录当次产品起点，不固定复用此旧 SHA。

## 发布边界与回退

本轮交付源码集成和上述构建/验收；没有替换开发电脑已安装的 3.15.3，没有生成完整新安装器，也没有发布自动更新 feed。`build:no-runtime-assets` 不代表 CLI 插件 bundle 已完整打包。

本地 Agent 的平台推理计费网关、完整本地会话共享和电脑键鼠控制仍未开放；3.16.2 的开源 CUA 包仍明确为 unavailable 占位，不能把合并上游当作这些能力已实现。

回退时可从合并前 `975db9e3` 创建独立产品修复分支，继续使用旧安装包。不要 reset 共享分支或把官方安装包作为织流更新推送。
